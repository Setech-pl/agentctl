# agentctl 0.23.0 — remote hosts

A task can now run on an owner-controlled Linux/WSL2 host over SSH while the dispatcher keeps durable state and a local report mirror. This release includes all 0.22.4 provider-hold, queue, report and status fixes.

- Configure `hosts` and put `host: pc` in a spec. Agentctl fetches the configured host clone, creates a worktree and runs the existing interactive provider adapter, setup, hooks and delivery checks there. Git, tmux, supported Node and a logged-in provider CLI are required on the host; agentctl itself is not.
- Shared account limits/holds cover local and remote tasks; host/provider caps add a second limit, visible in limits/capacity/board. Queued, never-started tasks can change location with `move --host pc|local`; running tasks cannot.
- Board badges identify remote rows, including queued/finished tasks. H shows cached health, tasks, limits and exact SSH attach commands. SSH loss is explicit, keeps the task's slot and retries with backoff.
- Watch restart rediscovers windows by durable task ID and refreshes tmux IDs. Remote adopt restores missing local metadata; resume recreates genuinely missing windows on the host, with remote hooks and report instructions.
- Remote GC measures finished worktrees/task files with bounded host walks and cached previews, then revalidates on the host before each owner-confirmed removal. Dirty/shared/linked/protected worktrees and reports stay; removal never uses force. Disk warnings identify each host work_dir. Remote branch deletion is not included.

The [host guide](../en/hosts.md) includes the complete WSL2/Windows portproxy/Mac setup for `krzet@192.168.2.64:2222`, reboot re-IP instructions, the first real task and troubleshooting. The C2 diagram includes the remote host. Automatic remote review is ordered as a separate task with `review: false`; it is not an automatic reviewer migration.

Validation uses fake SSH/tmux/provider fixtures without inference or network. A real PC/provider smoke remains the owner's first test. Credential-file presence is only a best-effort login signal; health probes do not prove token validity. Cooperative read-only tasks are not an OS sandbox.

## Owner publication / production upgrade

After reviewing the local release tag and completed gates:

```sh
git push origin rel-0.23.0 refs/tags/v0.23.0
gh release create v0.23.0 --title 'agentctl 0.23.0' --notes-file docs/release-notes/0.23.0.en.md docs/release-notes/0.23.0.pl.md
# Publishing this GitHub Release triggers the repository's OIDC npm workflow.
# After npm publication completes, upgrade production:
npm install -g @setech-pl/agentctl@0.23.0
agentctl watch --tmux --restart
agentctl board --tmux --restart
agentctl doctor
```

These are owner commands, not actions performed while preparing this release. Existing npm MCP processes need their client restarted to load the new installed code. For an existing clone-based stable installation, use `agentctl-update --ref v0.23.0` instead of npm installation.
