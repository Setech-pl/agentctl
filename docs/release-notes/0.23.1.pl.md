# agentctl 0.23.1 — zbiorcze informacje i aktualizacja

Ta instrukcja zastępuje notes 0.22.3 i obejmuje **0.22.0–0.23.1**. Wydanie łączy hosty zdalne 0.23.0 ze wszystkimi poprawkami 0.22.5–0.22.8, zachowując obie historie.

| Wersja | Zachowanie w tym wydaniu |
| --- | --- |
| 0.22.0 | CONSULT metodą delficką: podgląd/potwierdzenie/Accepted, niezależne zadania na detached HEAD, rundy i synteza, koszt/użycie, mapa tożsamości właściciela, zdarzenia i opcjonalny WALL. Współpraca read-only nie jest sandboxem systemu. |
| 0.22.1 | Pełne instrukcje EN/PL, samouczek od zera, referencje dostawców/MCP/konfiguracji, przykłady TUI i diagramy zadania/WALL/CONSULT. |
| 0.22.2–0.22.3 | Tanie podglądy MCP, walidacja startu przez watch po Accepted; atomowy snapshot z wiekiem/fallbackiem, trwałe potwierdzenia WALL i kursory tożsamości, pokrycie odbioru raportów, zachowanie SHA w YAML, przewijane pole Codex i komunikaty restartu watch. |
| 0.22.4 | Globalny hold dostawcy z terminem, automatyczne blokady quota/reset, kolejność usuwania z kolejki, overlap od bazy speca, uwagi outputs i ostatni poprawny blok, protokół attempt/werdyktu oraz wiek cache. |
| 0.22.5 | GC sprawdza każde repo: zmiany tracked/untracked i niewysłane commity; cache usuwany tylko jawnie, artefakty raportów chronione. Token answer działa po przewinięciu menu. Klasa `gate`, bezpieczne linki projektu i potwierdzanie MCP samym tokenem. |
| 0.22.6 | Odebrane raporty zwijane w kohortach; nieodebrane na górze planszy. `close --pulled --cohort` i MCP ponownie sprawdzają zakres. Konfigurowalne zwijanie i opcjonalne auto-close zachowują worktree. |
| 0.22.7 | Archiwum WALL po 14 dniach, listy domyślnie 7 dni, jedno przypomnienie po 24 h, nieaktywne pytania stale po 7 dniach; decyzje/kontrakty właściciela pozostają otwarte. Stałe ID/historia, cache archiwów, przełącznik planszy i wiek skrzynki. |
| 0.22.8 | Pin/unpin i keep GC, osobne sekcje usuwania/pominięć; próg startu 30 GiB, dwa setupy i szacunki worktree z wiekiem. Szczyt ze strefą czasu (GLM 14–18 Singapur w dni robocze), hold/short_only. Eskalacja uwagi po 15 min. Źródło/reset blokady, zgodność tożsamości/wygaśnięcia MCP, Kimi medium→high z ostrzeżeniem, błąd zamkniętych linków i doradcze zewnętrzne outputs. |
| 0.23.0 | Hosty po ścisłym multipleksowanym SSH, zdalne worktree/setup/dostawcy/hooki, lokalne kopie raportów, walidacja outputs, limity konta i hosta, znaczniki/H, backoff offline, przenoszenie kolejki, rediscovery/adopt/resume. |
| 0.23.1 | Poprawki obejmują hosty: GC pin/keep/cache/artefakty/niewysłane commity; świeży dysk work_dir, szczyt/hold przed setupem, limited, przewijane menu answer oraz snapshot bez SSH. |

[Instrukcja hostów i pierwszy test PC](../pl/hosts.md), [konfiguracja](../pl/configuration.md), [CHANGELOG](../../CHANGELOG.md). Zdalny GC nigdy nie wymusza usunięcia: zostawia raporty, symlinki, współdzielone/powiązane/chronione/brudne worktree i niewysłane commity; pomiary mają limit. Niejednoznaczne referencje cache chronią dane. Podgląd startu wymaga pomiaru hosta ≤60 s, rzeczywisty setup czyta świeże liczniki hosta (istniejącego rodzica dla nowego work_dir). Snapshot nie podstawia lokalnego dysku za zdalny.

Testy używają atrap SSH/tmux/dostawców, bez inferencji i sieci. Prawdziwy test PC pozostaje działaniem właściciela. Zdalny review to osobne jawne zadanie (`review: false`); obecność poświadczeń nie dowodzi poprawności logowania.

## Publikacja i aktualizacja właściciela

Wstaw pełny SHA wydania z REL0243.md zamiast `<sha>`; tych poleceń nie wykonano podczas przygotowania.

```sh
cd ~/Projects/agentctl
git push origin <sha>:main
git push origin v0.22.5 v0.22.6 v0.22.7 v0.22.8 v0.23.0 v0.23.1
gh release create v0.23.1 --draft --title 'agentctl 0.23.1' --notes-file docs/release-notes/0.23.1.en.md docs/release-notes/0.23.1.pl.md
```

Push tagu uruchamia CI; draft Release nie publikuje npm. **Publikacja GitHub Release** uruchamia `.github/workflows/publish.yml`: zgodny stabilny tag/wersja, instalacja/testy/typecheck/build i OIDC `npm publish --provenance --access public`, jeśli wersji jeszcze nie ma. Usunięcie `--draft` z `gh release create v0.23.1` publikuje Release od razu i uruchamia ten workflow.

Produkcja z klonu:

```sh
cd ~
cp ~/.agentctl/config.yaml ~/.agentctl/config.yaml.pre-0.23.1-$(date +%Y%m%d-%H%M%S)
~/Projects/agentctl/bin/agentctl-update --ref v0.23.1
agentctl watch --tmux --restart
agentctl board --tmux --restart
agentctl doctor
```

Zamknij Claude Desktop przez **⌘Q** i otwórz ponownie, aby MCP załadowało nowy kod. Zachowaj okna zadań; restart watch/board nie wymaga restartu agentów.

Scal z istniejącą konfiguracją, bez powielania głównych kluczy:

```yaml
disk:
  min_free_start_gb: 30
queue:
  max_parallel_setups: 2
board:
  pulled_collapse_after: 0
  pulled_auto_close_after: false
hosts:
  pc:
    ssh: krzet@192.168.2.64
    port: 2222
    work_dir: /home/krzet/agentctl-work
    repos: {agentctl: /home/krzet/src/agentctl}
    providers: [claude]
    limits: {claude: 1}
    env: {PATH: /home/krzet/.local/bin:/usr/local/bin:/usr/bin:/bin}
```

Zachowaj pozostałe ustawienia queue/board/disk i `mcp.allow`; dodaj `pin` tylko jeśli czaty mają zmieniać pin. Dopasuj PATH do Node i CLI w WSL. Domyślny szczyt nie wymaga nowego wpisu; zmieniaj `providers_config.glm.peak` świadomie.

Sprawdź `ssh -p 2222 krzet@192.168.2.64`, fingerprint i dostęp BatchMode; wykonaj konfigurację WSL2 i spec **PC-SMOKE-1** z instrukcji hostów. Uruchom `agentctl hosts --refresh`, `agentctl watch --tmux`, `agentctl new pc-smoke.md --no-wait-trust`, zaakceptuj folder trust przez SSH wypisane przez `agentctl attach PC-SMOKE-1`, sprawdź H i `agentctl pull PC-SMOKE-1`, zamknij zadanie i pokaż podgląd GC. To pierwszy prawdziwy test hosta/dostawcy; nie jest częścią automatycznej walidacji wydania.
