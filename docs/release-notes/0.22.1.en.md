# agentctl 0.22.1 — documentation release

0.22.1 documents the complete local workflow in matching English and Polish manuals. Runtime behavior is unchanged from v0.22.0. The owner publishes the commits/tags and GitHub release; this preparation performs no push, release creation or npm publish.

## New documentation

- Concise EN/PL front pages and a from-zero tutorial: Node/tmux/provider installation, clone/build, stable updater, first config/task, board, Claude desktop MCP, WALL and CONSULT.
- Feature/state and configuration references, every one of the 67 MCP tools and four permission groups, full input JSON Schema, provider/login/probe caveats and practical token economics.
- Project instruction inserts and longer ordering-agent guides explaining events-first, preview/confirmation/Accepted, report evidence, WALL as data and owner control of publication.
- Twenty real 160×45 TUI screenshots from an isolated fake-provider instance, with cohorts, after, queue_hold, trust/input, PASS/FAIL, limits/capacity and WALL filters/threads. No inference or account tokens.
- Local C4-PlantUML System Context/Containers and three sequence diagrams, each with source, SVG and PNG: task lifecycle/recovery, WALL and CONSULT.

Start at [English manual](../en/overview.md) or [Polska instrukcja](../pl/overview.md). The detailed [source map](../reference/source-map.md) ties behavior to code and deterministic tests.

## Highlights available across 0.20.x–0.22.x

- **0.20.x — GLM**: optional Z.ai Coding Plan provider via an owner-installed claude-glm wrapper, independent concurrency/token accounting, protected endpoint/secret handling and GLM-only AUTO_MODE_SERVER=0. First-run theme/security dialogs wait for the owner; failed starts retain their diagnostic window/screen. GLM plan quota remains n/d.
- **Accepted write path** (inherited from the preceding 0.19.x work and present throughout this series): new/queue confirms durably register a spec; watch validates and starts later. Other supported writes defer to watch with applied/failed events. Token replay avoids duplicate orders.
- **P94 after and queue_hold** (also inherited): missing in-progress verdict waits, rejected verdict blocks, corrected accepted reports auto-unblock; after_verdict customizes acceptance. MCP set_limits and CLI limits set update queue_hold live, preserving config comments/backup.
- **0.21.x — WALL**: channel communication across configured chats/tasks, identity/author/subscription checks, reply/status history, secret scanning and board views. Spec wall injects bounded read-only context; report wall_posts publishes once per attempt.
- **0.22.0 — CONSULT**: independent multi-provider Delphi rounds, best-effort anonymous revisions and reason-weighted synthesis. Detached read-only tasks, owner-only final identity map, optional WALL summary and restart-safe registration. Inherited automatic review is disabled for consultation tasks.
- **Regression suite** (introduced before 0.20.x and retained here): deterministic scenarios and measured previous-release proof/noProof catalog; every gate tier runs the catalog.

## Compatibility and limitations

No configuration migration or new runtime feature is introduced. Package/lockfile version is 0.22.1. Provider models and plan rules belong to providers; screen heuristics, best-effort anonymity and quota n/d remain explicit limits. Local stdio MCP needs a desktop client; browser/phone access is not a hosted endpoint.

The repository's existing published-GitHub-release workflow can publish the matching npm version through OIDC. Publishing the GitHub release is therefore an owner action with that existing downstream behavior; no workflow was changed here. Attach the Polish notes as an additional release asset or append their content to the release body.
