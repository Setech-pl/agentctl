# agentctl 0.26.4

This hotfix builds on 0.26.3. It makes `disk.auto_gc` safe to enable on a machine with thousands of tasks and worktrees and little free space.

One automatic run shares one inventory of task records, one index of declared links and real symlinks, and one read of the reports. It checks each candidate only when it is the next one needed. Every walk yields to the event loop, and a run stops at `disk.auto_gc.max_run_s` (default 300 s). In a fixture with 1500 records and 2000 worktrees with `node_modules`, a full dry run took 6 s, and the event loop never stopped for more than 20 ms.

Automatic GC now keeps:

- worktrees with git-ignored files outside `disk.auto_gc.ignored_ok` (default `node_modules`, `.cache/vite`, `dist`, `coverage`, `.turbo`);
- worktrees whose ignored files a report names;
- everything that queued, starting and needs-attention tasks still need.

Before a deletion, watch takes the same path claim as a start and reads the queue again. Only watch runs automatic GC; a CLI or MCP disk hold leaves it a request. Ctrl-C finishes the current item. A config reload stops a run only when `auto_gc` changed. The journal records run duration and bytes freed according to `statfs`.

Start with the recommended configuration in [configuration](../en/configuration.md#disk-management): 24 hours with `dry_run: true`, then `dry_run: false`.

Claude Code 2.1.332 rejects prompt-type SessionStart hooks. agentctl's task hooks are command-type and work with 2.1.323 and 2.1.332. A start names a non-command SessionStart hook found in your own or the project's settings. The first prompt is now confirmed by its transcript even when no hook runs, also on SSH hosts. See [troubleshooting](../en/troubleshooting.md).
