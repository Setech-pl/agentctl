# agentctl 0.26.4

Ta poprawka bazuje na 0.26.3. Dzięki niej `disk.auto_gc` można bezpiecznie włączyć na komputerze z tysiącami zadań i worktree oraz małą ilością wolnego miejsca.

Jeden przebieg automatycznego GC korzysta z jednego spisu zadań, jednego indeksu zadeklarowanych linków i dowiązań symbolicznych oraz jednego odczytu raportów. Każdą pozycję sprawdza dopiero wtedy, gdy jest potrzebna jako następna. Każde przeglądanie katalogów oddaje sterowanie pętli zdarzeń. Przebieg kończy się po `disk.auto_gc.max_run_s` (domyślnie 300 s). W teście z 1500 zadaniami i 2000 worktree z `node_modules` pełny przebieg próbny trwał 6 s, a pętla zdarzeń nie stała dłużej niż 20 ms.

Automatyczne GC zostawia teraz:

- worktree z plikami ignorowanymi przez git spoza `disk.auto_gc.ignored_ok` (domyślnie `node_modules`, `.cache/vite`, `dist`, `coverage`, `.turbo`);
- worktree, których ignorowane pliki wskazuje raport;
- wszystko, czego potrzebują zadania w kolejce, w trakcie startu i wymagające uwagi.

Przed usunięciem watch zajmuje ścieżkę tak samo jak start i ponownie czyta kolejkę. Automatyczne GC uruchamia tylko watch; start z CLI lub MCP zostawia mu zlecenie. Ctrl-C kończy bieżącą pozycję. Przeładowanie konfiguracji przerywa przebieg tylko po zmianie `auto_gc`. Dziennik zapisuje czas przebiegu i odzyskane bajty według `statfs`.

Zacznij od zalecanej konfiguracji z [konfiguracji](../pl/configuration.md#zarządzanie-dyskiem): przez 24 godziny `dry_run: true`, potem `dry_run: false`.

Claude Code 2.1.332 odrzuca hooki SessionStart typu prompt. Hooki zadań agentctl są typu command i działają z 2.1.323 i 2.1.332. Start wskazuje obcy hook SessionStart innego typu w Twoich lub projektowych ustawieniach. Pierwszy prompt potwierdza teraz transkrypt, także bez żadnego hooka i na hostach SSH. Zobacz [rozwiązywanie problemów](../pl/troubleshooting.md).
