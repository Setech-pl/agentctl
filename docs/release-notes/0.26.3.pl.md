# agentctl 0.26.3

Ta poprawka bazuje na 0.26.2. Start Codexa 0.167+ nie kończy się już błędem, gdy zapisany ekran awarii pokazuje gotowego Codexa. agentctl czyta teraz stopkę Codexa z poziomem usługi, np. `GPT-6.2-Sol medium Fast · <katalog>`. Wcześniej przez tę stopkę pole wpisywania było nieczytelne, więc oczekiwanie na gotowość nie mogło się zakończyć. Kontrola struktury pomija też kody ANSI i CRLF.

Oczekiwanie na gotowość wykonuje jeszcze jeden zrzut po upływie limitu. Limit rośnie z obciążeniem: wartość bazowa to `providers_config.<p>.ready_timeout_s` albo `agents.<p>.ready_timeout`, domyślnie 60 s, mnożona przez load1/rdzenie do 180 s. Start z kolejki po przekroczeniu limitu czeka jeszcze raz w tym samym oknie. Dopiero drugie przekroczenie ustawia `needs-attention` i zapisuje ekran.

Wiadomość wysłana do zajętego agenta ma po `delivery_confirm_s` stan `w kolejce agenta – niepotwierdzone` zamiast `needs-attention`. Hook albo wpis w transkrypcie potwierdza ją, gdy agent ją przetworzy. Odzyskiwanie zadań, które 0.26.2 zostawiło w `needs-attention`, opisuje [rozwiązywanie problemów](../pl/troubleshooting.md#start-codexa-kończy-się-błędem-did-not-show-its-input-prompt).
