# agentctl 0.26.3

This hotfix builds on 0.26.2. Codex 0.167+ starts no longer fail when the start-failure screen shows a ready Codex. agentctl now reads the Codex footer with a service tier, such as `GPT-6.2-Sol medium Fast · <dir>`. Before this release, that footer made the composer unreadable, so the readiness wait could not succeed. The structural check also ignores ANSI codes and CRLF.

The readiness wait takes one more capture after its deadline. Its timeout grows with load: the base is `providers_config.<p>.ready_timeout_s` or `agents.<p>.ready_timeout`, default 60 s, scaled by load1/cores up to 180 s. A queued start that times out waits once more in the same window. Only a second timeout sets `needs-attention` and saves the screen.

A follow-up sent while the agent is busy now stays `queued – unconfirmed` after `delivery_confirm_s` instead of becoming `needs-attention`. A hook or transcript entry confirms it after the agent processes it. See [troubleshooting](../en/troubleshooting.md#codex-start-fails-with-did-not-show-its-input-prompt) for recovering tasks left in `needs-attention` by 0.26.2.
