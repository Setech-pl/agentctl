# agentctl 0.25.3

- Watch sprawdza i uruchamia zadania z kolejki także wtedy, gdy pełny odczyt stanu przekracza limit czasu. Board i doctor pokazują pominięty etap i czas jego rozpoczęcia. Ukończony odczyt zostanie wykorzystany w kolejnym cyklu.
- Watch wysyła wiadomości z kolejki Codexa po potwierdzeniu pustego pola tekstowego, także gdy terminale nadal działają w tle.
- Po odzyskaniu wolnego miejsca watch ponawia zapisy stanu i snapshotu oraz odnotowuje jedno zdarzenie `zapis stanu wznowiony`. Przejściowy błąd zapisu przestaje oznaczać zadanie jako wymagające uwagi. Limit czasu odpowiedzi MCP nie przerywa rozpoczętego zapisu stanu.
- Gdy działa watch, MCP `gc` przekazuje mu przygotowanie planu i zwraca `request_id`. Wywołaj ponownie `gc` z tym ID, by zobaczyć plan i pobrać `preview_token`. Potwierdź tym tokenem wraz z `confirm: true`. Watch ponownie sprawdza zakres przed wykonaniem.
- CLI obsługuje `gc --force-dirty TASK [TASK...]`. Opcja `--force-dirty-all` obejmuje wszystkie kwalifikujące się lokalne worktree w selekcji. Przy wykonaniu planu wyświetla liczbę zmienionych plików i niewypchniętych commitów oraz wymaga odpowiedzi y/N na terminalu, także z `--yes`.
- Poziom i kolor dysku na board wynikają ze świeżego odczytu wolnego miejsca. Szacowany rozmiar worktree i wiek pomiaru są informacyjne.
- Watch publikuje każdą zmianę limitu globalnego lub kwoty raz na kanale WALL `agentctl`, ze starymi i nowymi wartościami oraz źródłem. Swoje prośby o decyzję oznacza jako `answered` po ustaniu oczekiwania lub `superseded` po zamknięciu bądź anulowaniu zadania. Powód zapisuje w historii WALL.

Jeśli korzystasz z klonu repozytorium, zaktualizuj instalację po udostępnieniu tagu w repozytorium źródłowym.

```sh
cd ~
~/Projects/agentctl/bin/agentctl-update --ref v0.25.3
agentctl doctor
```
