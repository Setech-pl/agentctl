# agentctl 0.22.1 — wydanie dokumentacji

0.22.1 opisuje pełny lokalny przepływ w odpowiadających sobie instrukcjach angielskiej i polskiej. Runtime pozostaje jak w v0.22.0. Właściciel publikuje commity/tagi i GitHub release; przygotowanie nie wykonuje push, tworzenia release ani npm publish.

## Nowa dokumentacja

- Zwięzłe strony główne EN/PL i samouczek od zera: Node/tmux/dostawcy, clone/build, stabilny updater, config/zadanie, board, MCP Claude desktop, WALL i CONSULT.
- Referencje funkcji/stanów/configu, wszystkich 67 narzędzi MCP i czterech grup uprawnień, pełny JSON Schema wejść, ograniczenia logowania/sond i ekonomia tokenów.
- Wstawki do instrukcji Projektu i dłuższy przewodnik zlecającego: events-first, podgląd/confirm/Accepted, dowody raportu, WALL jako dane i publikacja przez właściciela.
- Dwadzieścia prawdziwych zrzutów TUI 160×45 z izolowanej instancji atrap: kohorty, after, queue_hold, trust/input, PASS/FAIL, limity/capacity, filtry/wątki WALL. Bez inference i tokenów konta.
- Lokalne C4-PlantUML Context/Containers oraz trzy sekwencje ze źródłem, SVG i PNG: zadanie/odzyskiwanie, WALL i CONSULT.

Zacznij od [polskiej instrukcji](../pl/overview.md) lub [English manual](../en/overview.md). [Mapa źródeł](../reference/source-map.md) łączy zachowanie z kodem i testami deterministycznymi.

## Funkcje dostępne w serii 0.20.x–0.22.x

- **0.20.x — GLM**: opcjonalny Z.ai Coding Plan przez wrapper claude-glm właściciela, osobne sloty/tokeny, ochrona endpointu/sekretów i AUTO_MODE_SERVER=0 tylko GLM. Motyw/security/onboarding czeka na człowieka; nieudany start zachowuje okno/zapis ekranu. Kwota planu GLM to n/d.
- **Accepted** (odziedziczone z poprzedzających prac 0.19.x, dostępne w całej serii): confirm new/queue trwale rejestruje spec, watch waliduje/startuje później. Inne wspierane zapisy czekają na watch i zdarzenie applied/failed. Replay tokenu nie dubluje zleceń.
- **P94 after i queue_hold** (także odziedziczone): brak werdyktu w trakcie czeka, odrzucenie blokuje, poprawiony akceptowany raport sam odblokowuje; after_verdict zmienia akceptację. MCP set_limits i CLI limits set zmienia queue_hold na żywo z komentarzami/backupem.
- **0.21.x — WALL**: kanały skonfigurowanych czatów/zadań, kontrola autorów/subskrypcji, wątki/historia statusu, skan sekretów i board. Spec wall dodaje ograniczony kontekst tylko do odczytu, raport wall_posts publikuje raz na próbę.
- **0.22.0 — CONSULT**: niezależne rundy Delphi wielu dostawców, przybliżona anonimizacja rewizji i synteza według argumentów. Detached read-only, mapa autorów dopiero dla właściciela, opcjonalny WALL i rejestracja odporna na restart. Zadania konsultacji wyłączają odziedziczony auto review.
- **Regresje** (wprowadzone przed 0.20.x i zachowane): deterministyczne scenariusze i katalog zmierzonego dowodu/noProof na poprzednim wydaniu; każdy gate go uruchamia.

## Zgodność i ograniczenia

Bez migracji configu i nowych funkcji runtime. Wersja pakietu/lockfile to 0.22.1. Modele i reguły planu należą do dostawców; heurystyki ekranu, przybliżona anonimowość i n/d pozostają jawnymi ograniczeniami. Lokalny MCP stdio potrzebuje desktopu; web/telefon nie jest hostowanym endpointem.

Istniejący workflow opublikowanego GitHub release może publikować zgodną wersję npm przez OIDC. Publikacja release jest więc decyzją właściciela z tym istniejącym skutkiem; workflow nie zmieniono. Polskie notes można dołączyć jako asset albo dopisać ich treść do opisu release.
