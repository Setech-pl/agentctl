# agentctl 0.23.0 — hosty zdalne

Zadanie może działać na hoście Linux/WSL2 właściciela po SSH, a dispatcher zachowuje trwały stan i lokalną kopię raportu. Wydanie obejmuje wszystkie poprawki 0.22.4 dotyczące blokad dostawców, kolejki, raportów i statusu.

- Skonfiguruj `hosts` i dodaj `host: pc` do speca. Agentctl robi fetch klonu na hoście, tworzy worktree oraz uruchamia tam dotychczasowy interaktywny adapter dostawcy, setup, hooki i weryfikację dostarczenia promptu. Na hoście potrzebne są Git, tmux, obsługiwany Node i zalogowane CLI; agentctl nie jest wymagany.
- Limity/blokady konta obejmują zadania lokalne i zdalne, a limit host/dostawca dodaje drugi próg widoczny w limits/capacity/board. Nieuruchomione zadanie w kolejce zmienia lokalizację przez `move --host pc|local`; działające zadanie nie jest przenoszone.
- Znaczki hosta są także przy zadaniach w kolejce i zakończonych. H pokazuje cache zdrowia, zadania, limity i dokładne komendy SSH attach. Awaria SSH ma jawny stan, zachowuje slot i uruchamia ponawianie z backoff.
- Restart watch odnajduje okna po trwałym ID zadania i aktualizuje ID tmux. Zdalne adopt odtwarza brakujące metadane lokalne, a resume tworzy rzeczywiście brakujące okno na hoście, z jego hookami i ścieżką raportu.
- Zdalny GC mierzy zakończone worktree/pliki zadania z ograniczonym budżetem i cache podglądu, po czym ponownie sprawdza warunki na hoście przed każdym usunięciem potwierdzonym przez właściciela. Brudne/współdzielone/połączone/chronione worktree i raporty zostają; bez force. Ostrzeżenia dysku wskazują work_dir hosta. Zdalne gałęzie nie są usuwane.

[Instrukcja hostów](../pl/hosts.md) zawiera pełny setup WSL2/Windows portproxy/Mac dla `krzet@192.168.2.64:2222`, zmianę IP po restarcie, pierwszy rzeczywisty test i rozwiązywanie problemów. Diagram C2 obejmuje host zdalny. Zdalne review zamawiaj osobnym zadaniem z `review: false`; nie jest to automatyczna migracja reviewera.

Testy używają fałszywego SSH/tmux/CLI, bez inference i sieci. Pierwszy rzeczywisty test PC/dostawcy wykonuje właściciel. Obecność pliku logowania jest tylko wskazówką i nie dowodzi ważności tokenu. Odczytowe zadanie współpracującego agenta nie stanowi izolacji systemowej.

## Publikacja i aktualizacja produkcji przez właściciela

Po sprawdzeniu lokalnego taga i zakończonych gate’ów:

```sh
git push origin rel-0.23.0 refs/tags/v0.23.0
gh release create v0.23.0 --title 'agentctl 0.23.0' --notes-file docs/release-notes/0.23.0.en.md docs/release-notes/0.23.0.pl.md
# Opublikowanie GitHub Release uruchamia workflow publikacji npm przez OIDC.
# Po zakończeniu publikacji npm zaktualizuj produkcję:
npm install -g @setech-pl/agentctl@0.23.0
agentctl watch --tmux --restart
agentctl board --tmux --restart
agentctl doctor
```

To komendy dla właściciela, niewykonane przy przygotowaniu wydania. Procesy MCP z instalacji npm wymagają restartu klienta, aby wczytać nowy kod. Dla istniejącej stabilnej instalacji z klonu użyj `agentctl-update --ref v0.23.0` zamiast instalacji npm.
