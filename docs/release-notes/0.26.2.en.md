# agentctl 0.26.2

This hotfix builds on 0.26.1. An admission operation can wait for a 30-second command stage to finish. A queued start that has completed setup retries the state commit when the lock is busy. Prompt delivery and integrated worktree removal run outside the admission lock. Integrated removal uses `git.timeout_s`.

GC can again remove worktrees with local changes when the owner approves the named tasks. The override is journaled. Legacy Trash items need an agentctl ownership marker and appear in a separate section of the preview. MCP `gc` accepts `purge_trash: true` through preview and confirmation and reports reclaimed blocks by volume.

The owner can enable unattended cleanup with `disk.auto_gc.enabled`. Start with `dry_run: true` to see the plan in the `agentctl` WALL channel. On each low-space filesystem, watch reuses the GC protections, stops at the configured target or run budget, and reports what still blocks reclamation. `mcp.gc_scope` can reserve MCP GC for the owner CLI or limit each chat to its own cohorts.

When rolling back from 0.27.x, this release ignores its known newer configuration keys and reports them in one warning. See [disk management](../en/configuration.md#disk-management).
