# agentctl 0.22.3 — operacje i pełne instrukcje

Te informacje zastępują notes 0.22.1 i obejmują 0.20.x–0.22.3. Wydanie zachowuje historię operacyjną v0.22.2 (A1–A12) oraz dokumentację v0.22.1. Pakiet i lockfile mają wersję 0.22.3.

## Cała seria

- **0.20.x / GLM:** opcjonalny Z.ai Coding Plan przez wrapper claude-glm właściciela, niezależne sloty/tokeny, ochrona endpointu/sekretów i ustawienie trybu automatycznego tylko dla GLM. Pierwsze dialogi motywu/bezpieczeństwa czekają na właściciela; błąd startu zachowuje okno/ekran diagnostyczny. Kwota planu GLM pozostaje n/d. Dowód follow-up czyta właściwą wiadomość i parser transkryptu GLM.
- **0.21.x / WALL:** dopisywane kanały czatów/zadań, subskrypcje i autorzy, odpowiedzi/historia decyzji, skan sekretów, filtry/wątki boardu, ograniczony kontekst spec i wpisy raportu raz na próbę.
- **0.22.0 / CONSULT:** niezależne rundy delfickie wielu dostawców, stałe anonimowe rewizje i synteza ważąca argumenty, odłączone snapshoty tylko do odczytu, mapa autorów dla właściciela, opcjonalne podsumowanie WALL i rejestracja odporna na restart. Zadania konsultacji wyłączają odziedziczony automatyczny review. Read-only jest umową, nie izolacją systemową.
- **Odziedziczone zabezpieczenia:** trwałe Accepted, idempotentny token, after/after_verdict, czekanie/blokowanie i zwalnianie po poprawionym raporcie, bieżące queue_hold, deterministyczny katalog regresji i dowody na poprzednim wydaniu.

## Operacje 0.22.2 zachowane w 0.22.3

- Podgląd new/queue wykonuje tanie sprawdzenia. Watch po przyjęciu waliduje bazy, nakładanie, worktree, limity i dysk; błędy przychodzą jako zdarzenia. Accepted nie dowodzi startu/ukończenia.
- Ograniczone odczyty MCP korzystają z atomowego snapshotu ticka młodszego niż dwa interwały, podają wiek i oznaczają odczyt awaryjny. Doctor ze snapshotu nie uruchamia CLI dostawców; diagnostykę instalacji wykonuje CLI doctor. GC preview może oddać Accepted/request_id na czas przygotowania; set_limits nie zależy od start.lock.
- WALL zapisuje synchronicznie, bez czekania na watch. Skonfigurowane as wyznacza kursor (jawny client nadpisuje), WALL omija kohorty, sekcja WALL do Ciebie (open) powtarza otwarte sprawy, nieznany czat dostaje ostrzeżenie, a rzeczywiste własne wpisy mają (yours).
- Każdy zapis z podglądem przyjmuje confirm samym tokenem w tej samej sesji. Przewinięte wielowierszowe pole Codexa zachowuje własność, a send uwzględnia potwierdzenie w transkrypcie.
- get_report podsumowanie/pierwsza pełna strona domyślnie oznacza pulled; mark_pulled false wyłącza, true jawnie potwierdza. Pozostałe strony zbierają pokrycie w dowolnej kolejności; sekcje domyślnie nie oznaczają. Skrót pull_ready pozostaje osobny od pełnego odbioru i oceny mark.
- SHA YAML pozostają tekstem; działają pierwsze linie Verdict/Werdykt i zwięzłe mapy outputs; placeholdery są uwagą. Zwinięte pytania Codexa zachowują tekst z namespacowanych narzędzi. Powrót watch emituje WATCH WZNOWIONY.

## Poprawki i dokumentacja 0.22.3

Brak bazy spec wskazuje lokalną gałąź domyślną: `base main not found – default branch is master`. Pierwszeństwo ma lokalny origin/HEAD; bez niego HEAD main/master, inaczej domyślna jest nieznana. Bez fetch i automatycznej podmiany. Popraw spec i ponów.

Pomoc boardu mieści się w terminalu i przewija ↑↓/PgUp/PgDn; pozostałe klawisze wracają. To poprawka rzeczywistego nadpisywania nagłówka. Odświeżono tylko zrzut pomocy, na izolowanych atrapach dostawców.

Zgodne instrukcje EN/PL obejmują instalację/pierwsze zadanie, 67 narzędzi MCP/cztery grupy i generowane schematy JSON, konfigurację, ekonomię dostawców/tokenów oraz wstawki Projektu i zasady zlecającego. Dwadzieścia prawdziwych widoków TUI uzupełniają lokalne C4 i sekwencje zadania/WALL/CONSULT. Sekwencje zadania i WALL zaktualizowano i wyrenderowano lokalnie. Zacznij od [polskiej instrukcji](../pl/overview.md) lub [English manual](../en/overview.md).

## Publikacja i granice

Push tagu uruchamia CI macOS z Node 22.14.0 i 26.13.0: instalacja, docs/Mermaid, typy, izolowane testy, build i pack dry-run. Nie publikuje npm. Opublikowanie GitHub Release uruchamia istniejący Publish npm: kontrola zgodności stabilnego tagu/wersji i npm, testy/build, sprawdzenie rejestru i publikacja OIDC, jeśli wersji brak. Workflow pozostaje bez zmian. Utworzenie GitHub Release jest zatem także wyzwalaczem publikacji npm. Dołącz `0.22.3.pl.md` jako asset lub dopisz treść do opisu wydania.

Rozpoznawanie ekranów i anonimizacja są heurystyczne; kwoty mogą być n/d. Lokalny MCP to desktopowe stdio, nie publiczny endpoint WWW/telefonu. Trust oraz integracja/publikacja należą do właściciela.
