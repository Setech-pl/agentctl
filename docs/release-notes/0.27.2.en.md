# agentctl 0.27.2

- Release checks now exercise 1,500 task records under production-shaped load and seal the candidate SHA and fixture inputs throughout the run.
- Clone upgrades check watch progress, admission, MCP responses and board rendering. A failed check restores the previous stable version and configuration and sends an owner WALL info.
- `agentctl canary --from <AGENTCTL_HOME> --minutes 30` runs a sanitized shadow test before the upgrade.
- Watch prioritizes repeatedly skipped stages and restarts a stalled stage loop. Missing windows are rechecked, complete reports in idle panes become ready, transient CLI failures retry, and terminal dependencies and ambiguous verdicts are reported.
- Queue previews name worktree volumes. State and cache get a separate 5 GiB floor. Quota removal, stale usage readings and deferred output checks have explicit semantics.
- High load raises alerts by default. Set `queue.hold_on_load: true` to hold admission above `capacity.load_threshold`. The queue shows the reason.
- Watch runs launch retries in the background with command deadlines. Interrupted legacy launches require an explicit `agentctl resume TASK`.
- Includes the 0.26.1 production hotfix for bounded checkout and setup, automatic start-lock recovery, supervised watch restarts, interrupted start recovery, and scoped GC delete modes.
- Git protects uncommitted worktree files during GC. `--force-dirty` can include clean worktrees with unpushed commits.
- After upgrading, quit all Claude chats with ⌘Q and reopen them. Pre-0.27 MCP servers cannot set limits. Before a manual rollback run `agentctl config downgrade-check --to 0.26.x`.
