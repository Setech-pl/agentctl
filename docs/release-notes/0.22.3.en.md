# agentctl 0.22.3 — operations and complete manuals

These notes supersede the 0.22.1 documentation notes and cover 0.20.x–0.22.3. This release preserves both the v0.22.2 operations history (A1–A12) and v0.22.1 documentation history. Package and lockfile versions are 0.22.3.

## Across the series

- **0.20.x / GLM:** optional Z.ai Coding Plan provider through the owner's claude-glm wrapper, independent concurrency/token accounting, protected endpoint/secret handling and GLM-only automatic-mode setting. First-run theme/security dialogs wait for the owner; failed starts retain diagnostic windows/screens. GLM plan quota remains n/d. Queued follow-up proof reads the correct message and GLM transcript parser.
- **0.21.x / WALL:** append-only channels across configured chats/tasks, subscriptions/author checks, replies and decision history, secret scanning, board filters/threads, bounded spec context and once-per-attempt report posts.
- **0.22.0 / CONSULT:** independent multi-provider Delphi rounds, stable anonymous revisions and reason-weighted synthesis, detached read-only snapshots, owner-only identity map, optional WALL summary and restart-safe registration. Consultation tasks disable inherited automatic review. Read-only is a cooperative boundary, not OS isolation.
- **Inherited queue/report safeguards:** durable Accepted requests, idempotent token replay, after/after_verdict waiting and blocking, automatic release after a corrected accepted report, live queue_hold updates, deterministic regression catalog and previous-release proof.

## 0.22.2 operations retained in 0.22.3

- New/queue previews run cheap checks only. Watch validates bases, overlap, worktrees, limits and disk after acceptance; failures arrive through events. Accepted never proves start/completion.
- Bounded MCP reads use the atomic tick snapshot when younger than two watch intervals, report its age and label stale/unavailable fallback. Snapshot doctor avoids provider CLI probes; use CLI doctor for installation diagnostics. GC preview can return Accepted/request_id while watch prepares it; set_limits stays independent of start.lock.
- WALL writes validate and append synchronously without waiting for watch. Configured `as` scopes chat cursors (explicit client overrides), WALL bypasses cohort filters, `WALL do Ciebie (open)` repeats unresolved items, unknown chats receive a warning and actual own posts show `(yours)`.
- Every previewed write accepts token-only confirm in the same session. Scrolled multiline Codex drafts retain ownership and send verification includes transcript acknowledgement.
- get_report summary/first full page marks pulled by default; mark_pulled false opts out, true explicitly acknowledges. Other pages accumulate complete coverage in any order; sections do not mark by default. pull_ready summary remains distinct from full acknowledgement and human mark.
- YAML SHA identifiers stay strings; Verdict/Werdykt first lines and compact output mappings work; placeholders are findings. Collapsed Codex questions retain namespaced question text. Watch recovery emits WATCH WZNOWIONY.

## 0.22.3 fixes and documentation

Missing spec bases now identify the locally known default: `base main not found – default branch is master`. Local origin/HEAD wins; absent it, main/master HEAD is used, otherwise the default is unknown. No fetch or automatic substitution occurs. Correct the spec and retry.

Board help now fits terminal height and scrolls with ↑↓/PgUp/PgDn; other keys return. This fixes real header overdraw. Only the help screenshot was recaptured using isolated fake providers.

Matching EN/PL manuals cover installation/first task, all 67 MCP tools/four permission groups with generated JSON schemas, configuration, provider/token economics and Project/ordering-agent instructions. Twenty real TUI views accompany local C4 and task/WALL/CONSULT diagrams. Task lifecycle and WALL sequences have been updated and rendered locally. Start with the [English manual](../en/overview.md) or [Polska instrukcja](../pl/overview.md).

## Publication and limits

A GitHub tag push triggers CI on macOS for Node 22.14.0 and 26.13.0: install, docs/Mermaid, types, isolated tests, build and pack dry-run. It does not publish npm. Publishing a GitHub Release triggers the existing Publish npm workflow: matching stable tag/version and npm-version guards, tests/build, registry check, then OIDC npm publish if that version is absent. Workflow behavior is unchanged. Creating the GitHub release is therefore also an npm-publication trigger. Attach `0.22.3.pl.md` as a release asset or append its content to the release body.

Provider screen detection and anonymous text stripping remain heuristic; quotas may be n/d. Local MCP is desktop stdio, not a hosted web/phone endpoint. Trust and integration/publication remain owner decisions.
